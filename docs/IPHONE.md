# iPhone: Expo Go та локальний API Windows

1. Під’єднайте iPhone і Windows-ПК до однієї приватної Wi-Fi/LAN-мережі. Гостьова мережа з ізоляцією клієнтів не підходить. Перевірте, чи VPN не змінює маршрути.
2. На ПК виконайте `ipconfig` або `Get-NetIPConfiguration`. Потрібна IPv4 фізичного Ethernet/Wi-Fi-адаптера зі шлюзом, а не адреса WSL, Docker, VPN або loopback.
3. З кореня проєкту виконайте `./scripts/configure_mobile_lan.ps1`. Для неоднозначних мереж використайте `-Address 'ВАШ_IP'`. Скрипт змінює лише `EXPO_PUBLIC_API_URL` і зберігає інші рядки локального `.env`.
4. Переконайтесь, що SQL Server працює, міграція виконана, FastAPI слухає `127.0.0.1:8000`, ASP.NET — `http://0.0.0.0:5100`.
5. У Safari iPhone відкрийте `http://<IPv4-ПК>:5100/api/health`. Очікується JSON `status: ok`, `database: true`, `ai: true`. 503 означає, що HTTP уже доступний, але один із серверних компонентів не готовий.
6. Якщо браузер телефона не бачить API, перевірте мережевий профіль Windows. Для довіреної приватної мережі можна дозволити **лише потрібний вхідний TCP-порт 5100 для Private і LocalSubnet**. Окремо Metro потребує 8081. Не вимикайте Firewall і не відкривайте SQL або FastAPI назовні. Приклади точкових правил адміністратор Windows може створити самостійно:

```powershell
New-NetFirewallRule -DisplayName 'AI Bird Lab API LAN' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5100 -Profile Private -RemoteAddress LocalSubnet
New-NetFirewallRule -DisplayName 'AI Bird Lab Expo LAN' -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8081 -Profile Private -RemoteAddress LocalSubnet
```

Ці правила автоматично не застосовувалися. Вмикайте їх лише у власній довіреній мережі.

7. У `mobile-app` виконайте `npm ci` і `npm start -- --clear`. Після кожної зміни `.env` перезапускайте Metro; значення `EXPO_PUBLIC_*` вбудовуються у JS bundle.
8. Встановіть сумісний Expo Go. Поточний проєкт — SDK 57, React Native 0.86.3 за матрицею `expo/bundledNativeModules.json`. Якщо Expo Go повідомляє про несумісний SDK, звірте підтримуваний SDK із [офіційною інструкцією](https://docs.expo.dev/get-started/create-a-project/), перш ніж змінювати залежності. `expo-doctor` і `expo install --check` мають пройти після зміни.
9. Скануйте QR у консолі камерою iPhone → Open in Expo Go. Якщо Expo Go вимагає вхід, виконайте `npx expo login` і використайте той самий Expo-акаунт у клієнті. Це не обліковий запис AI Bird Lab.
10. Дозвольте Expo Go доступ до **Local Network**, а під час використання фото/запису — до камери, Фото та мікрофона. Відмову можна змінити в Settings → Expo Go. Застосунок обробляє відмову і скасування вибору без створення аналізу.

## HTTP, HTTPS та Tunnel

Для довіреної локальної мережі у development використовується HTTP. Дозволи та ATS-політика належать встановленому Expo Go: зміни `Info.plist` у `app.json` самі не перебудовують Expo Go. Якщо конкретна версія iOS/Expo Go блокує HTTP, використайте HTTPS reverse proxy з довіреним сертифікатом та задайте його URL. Не додавайте глобальні ATS-виключення і не вимикайте перевірку сертифікатів.

Self-signed HTTPS-сертифікат ASP.NET на ПК не стає автоматично довіреним на iPhone. Для локальної перевірки простіше використати дозволений Expo Go LAN HTTP; для HTTPS потрібен довірений телефоном сертифікат. Не обходьте попередження браузера про сертифікат.

`npx expo start --tunnel` прокладає тунель **лише до Metro**. Адреса `EXPO_PUBLIC_API_URL=http://192.168...:5100` залишається приватною. Якщо телефон поза LAN, backend потребує окремого доступного HTTPS endpoint. Центральний API тепер використовує Identity, приватну історію та Bearer-сесію в SecureStore. Публічне розгортання потребує належного HTTPS та окремої перевірки безпеки.

## Приймальна перевірка на фізичному телефоні

- Відкрити `/api/health` у Safari.
- Зробити фото камерою, перевірити preview, TOP-3 та джерела.
- Побачити той самий ID у веб-історії після оновлення; перевірити й зворотний напрямок.
- Обрати аудіофайл; окремо записати до 59 секунд, відтворити та відправити M4A.
- Перевірити відмову в дозволах, скасування picker, недоступний backend, поворот і SafeArea.
- Переглянути галерею, статистику, порівняння та CSV Share.
- Видалити власний тестовий запис із підтвердженням і переконатися, що він зник у вебі.

Цей список потребує фізичного iPhone. Перевірка JS bundle, HTTP-протоколу та expo-doctor його не замінює.


## Асинхронна перевірка RabbitMQ

Після upload очікуйте HTTP 202 та UUID: «Очікування в черзі» → «Обробка» → «Аналіз завершено» або «Помилка аналізу». Відкрийте завершений результат у спільній історії. Згорніть Expo Go під час черги/обробки та поверніться: polling повинен відновитися без повторного upload. Перезапустіть Expo Go: ID останнього завдання має прочитатися з документного сховища. Перевірте відсутність запитів після втрати фокусу екраном. Ці пристрійні кроки ще не виконувалися автоматично; актуальні докази — `docs/RABBITMQ_VERIFICATION.md`. Наявну LAN-адресу API під час інтеграції не змінювали.
